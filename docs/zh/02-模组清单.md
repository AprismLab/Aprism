## 1. 执行摘要

本文档规定了 Aprism Loader 用于跨 Minecraft Java Edition（JE）与 Bedrock Edition（BE）描述、校验并加载模组的规范化清单格式。该清单名为 `aprism.manifest.json`，是 `fabric.mod.json`（Fabric/Quilt）、`neoforge.mods.toml` / `mods.toml`（NeoForge/Forge）、`litemod.json`（LiteLoader）以及 Bedrock `manifest.json` 在字段语义层面的严格超集。单个清单即可描述一个为多个 JE loader 提供独立 provider 块的模组，也可描述一个以 C++、Lua、C#、Rust 或 Script API 编写的 Bedrock 模组。

该清单是以下内容的唯一权威来源：模组身份、版本、运行环境、entrypoints、mixin、依赖范围、按 loader 的覆盖项，以及语言运行时的选择。Aprism 会优先读取 `aprism.manifest.json`；当其缺失时，回退到旧版清单的自动发现机制，并在加载时将其投影至 Aprism schema 中。接口契约是单调的：字段只增不减、不改名；废弃某字段需至少提前一个发布周期公告。

## 2. 设计原则

1. **超集，而非替代。** 凡存在于 `fabric.mod.json`、`quilt.mod.json`、`neoforge.mods.toml`、`mods.toml`、`litemod.json` 与 Bedrock `manifest.json` 中的字段，在 `aprism.manifest.json` 中均有明确的映射。针对任一旧版格式编写的模组仍可被加载。
2. **自动发现回退。** 当 pack 中不存在 `aprism.manifest.json` 时，Aprism 会按既定顺序（见第 5 节）探测旧版清单，并合成一份内存中的 Aprism 清单。在所有解析与校验场景中，合成清单与显式清单等效，唯一例外是合成清单无法承载 Aprism 专有字段。
3. **版本感知。** JE pack（`.aje`）与 BE pack（`.abe`）使用相同文件名，但顶层结构不同。JE 清单为扁平的 JSON 对象；BE 清单为 Bedrock `manifest.json` 的超集，保留 `format_version`、`header`、`modules` 与 `dependencies` 以保证原生 Bedrock 兼容性，所有 Aprism 专有数据均嵌套于 `aprism` 对象之下。
4. **语言无关。** 通过 `language` / `type` 字段选择运行时（java/cpp/lua/csharp/rust/javascript）以及所适用的入口契约。该机制沿用 Bedrock 上 LeviLamina 的先例，并推广至 JE。
5. **按 loader 的 provider 块。** 多 loader 模组在顶层声明一份契约，仅对差异部分按 loader（`fabric`、`neoforge`、`forge`、`quilt`、`liteloader`）进行覆盖。覆盖为合并而非替换。
6. **单调接口。** `schemaVersion` 仅在工具链无法安全忽略的纯增量变更时递增。一旦某字段发布，其名称与类型即永久稳定。

## 3. aprism.manifest.json Schema（JE `.aje` pack）

### 3.1 字段参考

| 字段 | 类型 | 必填 | 描述 | 起始版本 |
|---|---|---|---|---|
| `schemaVersion` | integer | 是 | 清单 schema 版本。当前为 `1`。 | 1 |
| `id` | string | 是 | 模组标识符。小写 `[a-z0-9_-]`，2-64 字符，必须以字母开头。 | 1 |
| `version` | string (SemVer) | 是 | 模组版本。SemVer 2.0.0 超集；允许构建元数据。 | 1 |
| `displayName` | string | 否 | 人类可读名称。默认为 `id`。 | 1 |
| `description` | string | 否 | 简短描述。 | 1 |
| `authors` | array of string \| object | 否 | 作者。对象形式：`{name, email, website}`。 | 1 |
| `contributors` | array of string \| object | 否 | 贡献者。结构与 `authors` 相同。 | 1 |
| `license` | string \| array of string | 否 | SPDX 标识符或自由文本。 | 1 |
| `icon` | string | 否 | pack 内指向 PNG 图标的路径（推荐 128x128 或 256x256）。 | 1 |
| `contact` | object | 否 | `{homepage, sources, issues, email, irc, discord}`。 | 1 |
| `homepage` | string | 否 | `contact.homepage` 的便捷别名。 | 1 |
| `environment` | string | 否 | 取值为 `*`、`client`、`server`、`dedicated_server` 之一。默认 `*`。 | 1 |
| `entrypoints` | object | 否 | 将阶段映射到入口描述符数组。见 3.3。 | 1 |
| `mixins` | array | 否 | Mixin 配置引用。见 3.4。 | 1 |
| `accessWidener` | string | 否 | access widener 文件路径（Fabric 兼容格式）。 | 1 |
| `depends` | object | 否 | 硬依赖。键为 mod id，值为版本范围。 | 1 |
| `recommends` | object | 否 | 软依赖；若存在则在本模组之前加载。 | 1 |
| `suggests` | object | 否 | 信息性建议；永不导致加载失败。 | 1 |
| `breaks` | object | 否 | 与本模组无法共存的版本。 | 1 |
| `conflicts` | object | 否 | 可共存但不被支持的版本。 | 1 |
| `provides` | array of string | 否 | 本模组可满足的别名 id（例如替代型模组）。 | 1 |
| `languageAdapters` | object | 否 | 语言 id 到 adapter 类的映射。 | 1 |
| `language` | string | 否 | 运行时语言。默认 `java`。取值为 `java`、`cpp`、`lua`、`csharp`、`rust`、`javascript` 之一。 | 1 |
| `platforms` | object | 否 | 按 loader 的 provider 块。见 3.5。 | 1 |
| `aprismApi` | string (range) | 否 | 所需 Aprism API 版本范围。 | 1 |
| `minecraft` | string (range) | 否 | 所需 Minecraft 版本范围。 | 1 |
| `java` | object \| string | 否 | 所需 Java 版本。`{min, max}` 或范围字符串。 | 1 |
| `custom` | object | 否 | 自由格式元数据；由工具链定义。不得影响加载顺序。 | 1 |
| `depends` 也可包含保留键 `aprism`、`minecraft`、`java`，作为上述顶层范围的别名。 | | | | |

### 3.2 身份与版本

`id` 必须匹配 `^[a-z][a-z0-9_-]{1,63}$`。id 在磁盘上区分大小写，但在依赖匹配时不区分大小写，与 Fabric 一致。`version` 必须按 SemVer 2.0.0 解析，并允许两项扩展：前导 `=`（Maven 兼容）以及 `+build` 后缀（与未限定版本比较时视为相等）。两个具有相同 `id` 但不同 `version` 的模组无法共存；较高版本胜出，较低版本以 shadowed 记录于日志。

### 3.3 `entrypoints`

`entrypoints` 是一个对象，其键为阶段名，值为入口描述符数组。描述符可以是全限定类名（`com.example.MyMod`）、`Class::method` 对（`com.example.MyMod::init`），或对象 `{adapter, value}`，其中 `adapter` 选定一个 `languageAdapters` 条目（默认 `java`）。已识别的阶段键：

| 阶段 | 调用时机 | 入口签名契约（Java） |
|---|---|---|
| `main` | 共享初始化，双侧 | `void init()`（Fabric `ModInitializer`） |
| `client` | 仅客户端初始化 | `void onInitializeClient()` |
| `server` | 专用服务端初始化 | `void onInitializeServer()` |
| `aprism` | Aprism 生命周期钩子 | `void onAprismInit(AprismContext)` |
| `preLaunch` | 游戏主循环之前；少见 | `void onPreLaunch()` |
| `jdk` | JVM classpath 垫片 | 仅类名 |

非 Java 语言使用第 10 节中声明的语言专属契约。

### 3.4 `mixins`

每个元素既可以是 Mixin 配置 JSON 的字符串路径（如 `"mixins.client.json"`），也可以是对象 `{config, environment}`，其中 `environment` 取值为 `*`、`client` 或 `server`。被引用的 Mixin 配置保留规范的 `*.mixins.json` 形态：`package`、`required`、`minVersion`、`compatibilityLevel`、`priority`、`mixinPriority`、`mixins`、`client`、`server`、`refmap`、`injectors`、`plugin`、`overwrites`。

### 3.5 `platforms`（provider 块）

`platforms` 是以 loader id 为键的对象：`fabric`、`quilt`、`neoforge`、`forge`、`liteloader`。每个值是一个对象，可覆盖以下任意字段：`entrypoints`、`mixins`、`depends`、`recommends`、`suggests`、`breaks`、`conflicts`、`accessWidener`、`languageAdapters`、`language`、`jars`、`transformers`。覆盖以深度合并方式进行：数组拼接（按值去重），对象按键合并，标量以覆盖方为准。provider 块还可声明 `enabled: false`，以指示 Aprism 即便存在对应 jar 也跳过该 loader。

```json
{
  "platforms": {
    "fabric":  { "depends": { "fabricloader": ">=0.15.0" } },
    "neoforge":{ "depends": { "neoforge": ">=20.4.0" }, "accessWidener": null },
    "forge":   { "enabled": false }
  }
}
```

## 4. aprism.manifest.json Schema（BE `.abe` pack）

对于 Bedrock，清单是原生 `manifest.json` 的严格超集。所有 Bedrock 字段（`format_version`、`header`、`modules`、`dependencies`、`capabilities`、`metadata`、`subpacks`）均原样保留，使 Bedrock 自身及常规工具链仍可解析该 pack。Aprism 专有数据位于单个 `aprism` 对象之下。

### 4.1 Aprism 扩展字段（位于 `aprism` 下）

| 字段 | 类型 | 必填 | 描述 | 起始版本 |
|---|---|---|---|---|
| `aprism.schemaVersion` | integer | 是 | Aprism BE 清单 schema 版本。当前为 `1`。 | 1 |
| `aprism.modId` | string | 是 | id 规则与 JE 相同。在加载图中必须唯一。 | 1 |
| `aprism.version` | string (SemVer) | 是 | 模组版本。与 `header.version`（Bedrock 三元组）相互独立。 | 1 |
| `aprism.language` | string | 是 | 取值为 `cpp`、`lua`、`csharp`、`rust`、`javascript` 之一。 | 1 |
| `aprism.nativeEntrypoints` | object | 条件 | 当 `language` != `javascript` 时必填。按平台的二进制引用。 | 1 |
| `aprism.scriptEntrypoints` | object | 条件 | 当 `language` = `javascript` 时必填。映射到 Script API `entry`。 | 1 |
| `aprism.aprismApiVersion` | string (range) | 是 | 所需 Aprism BE API 版本范围。 | 1 |
| `aprism.gameVersionRange` | string (range) | 是 | 所需 Minecraft Bedrock 版本范围。 | 1 |
| `aprism.depends` | object | 否 | Aprism BE 模组依赖（modId -> 范围）。 | 1 |
| `aprism.compatibleJE` | object | 否 | 用于 JE 转换而来的模组：`{jeModId, jeVersionRange, conversionProfile}`。 | 1 |
| `aprism.mixins` | array | 否 | 可选的 LeviLamina 风格钩子描述符，供 C++ 运行时使用。 | 1 |
| `aprism.custom` | object | 否 | 自由格式。 | 1 |

## 5. 清单发现与解析顺序

Aprism 加载 pack 时，按以下顺序获取清单：

1. **JE `.aje` pack。** 在 pack 根目录查找 `aprism.manifest.json`。若存在，则按 JE schema 解析并校验。
2. **JE 回退。** 若 `aprism.manifest.json` 缺失，按以下顺序探测：
   1. `fabric.mod.json`（Fabric pack）。
   2. `quilt.mod.json`（Quilt pack；缺失时回退到内嵌的 `fabric.mod.json`）。
   3. `META-INF/neoforge.mods.toml`（NeoForge pack）。
   4. 带 `loaderVersion` 启发式的 `META-INF/mods.toml`（Forge pack）。
   5. `litemod.json`（LiteLoader pack）。
   首个匹配项被投影至 Aprism schema（见第 8 节）。若发现的文件隐含了某个 provider 块（例如 `fabric.mod.json` 隐含 `platforms.fabric`），投影过程将填充该块。
3. **BE `.abe` pack。** 在 pack 根目录查找 `manifest.json`（Bedrock 规范文件）。若存在 `aprism` 对象，则解析之。若不存在，则将该 pack 视为普通 Bedrock pack，Aprism 仅暴露 Script API 入口（不进行原生加载）。
4. **嵌入 `.abe` 内的 `.aje`。** `.abe` pack 可包含一个 `je-source/` 目录，其中嵌入一个 `.aje`，用于转换来源字段 `aprism.compatibleJE`。此信息仅供参考。

若以任何形式都未发现清单，pack 将以 `CHKAPRISM-MANIFEST-001` 拒绝。

## 6. 版本范围语法

Aprism 采用 SemVer 范围语法，并显式兼容 Maven 范围。其文法（区分大小写）：

```
range      := clause ( "," clause )*
clause     := op? version
op         := ">=" | "<=" | ">" | "<" | "=" | "~" | "^"
version    := semver ( "-" pre )? ( "+" build )?
```

逗号表示逻辑与。竖线字符 `|` 表示逻辑或，其优先级低于逗号：`>=1.0 <2.0 | >=3.0` 匹配 `[1.0, 2.0)` 或 `[3.0, +inf)`。裸通配符 `*` 匹配任意版本。空字符串非法。

| 运算符 | 含义 |
|---|---|
| `=` | 等于（无运算符时亦隐含相等）。 |
| `>` `<` `>=` `<=` | 比较。 |
| `^` | 兼容至：同一主版本。`^1.2.3` = `>=1.2.3 <2.0.0`。`^0.2.3` = `>=0.2.3 <0.3.0`。 |
| `~` | 补丁级别：`~1.2.3` = `>=1.2.3 <1.3.0`。`~1.2` = `>=1.2.0 <1.3.0`。 |

**Maven 兼容。** 对 Forge 风格的范围，Aprism 亦接受 Maven 方括号：`[1.0,2.0)`、`(,3.0]`、`[1.5.0]`。这些会在内部转换为 SemVer 形式。

**快照与预发布版。** 快照版本采用 `26w01a` / `1.21-snapshot` 形式。Aprism 将其规范化为 SemVer 预发布标签（`1.21.0-snapshot.26w01a`）。范围可包含快照选择器：`>=1.21-snapshot` 匹配所有快照及正式版。

## 7. 依赖解析算法

Aprism 在 classloading 之前解析依赖。算法如下：

1. **收集。** 构建一个图，其中每个节点为 `(modId, version)`，每条边为 `depends` 或 `recommends` 中声明的依赖。
2. **满足。** 对每条 `depends` 边，按 id（含 `provides` 别名）定位候选模组。若无候选，则以 `CHKAPRISM-DEP-001`（缺少硬依赖）失败。对 `recommends`，缺失候选仅记录日志并被容忍。
3. **范围校验。** 对每个已定位的候选，校验其 `version` 是否满足所声明范围。失败：`CHKAPRISM-DEP-002`（版本不匹配）。
4. **breaks/conflicts。** 对每个已加载模组，针对图评估 `breaks`。任何匹配：`CHKAPRISM-DEP-003`（破坏）。`conflicts` 匹配仅记录警告并继续。
5. **provides 去重。** 若两个模组 `provides` 同一别名，较高 `version` 胜出；较低者以 `CHKAPRISM-DEP-004`（重复 provides）卸载。
6. **拓扑排序。** 对模组排序，使每个 `depends` 与 `recommends`（在存在时）前驱均排在其后继之前。为确定性起见，平手按 id 字典序打破。
7. **环检测。** `depends` 中的环为致命错误：`CHKAPRISM-DEP-005`（循环依赖）。`recommends` 中的环仅记录日志并任意打破。
8. **Aprism/Minecraft/Java。** 保留依赖 `aprism`、`minecraft`、`java` 首先针对运行时求值；失败将在任何模组初始化之前中止加载。

## 8. 迁移与兼容性

### 8.1 `fabric.mod.json` -> `aprism.manifest.json`

| fabric.mod.json | aprism.manifest.json |
|---|---|

| `id` | `id` |
| `version` | `version` |
| `name` | `displayName` |
| `description` | `description` |
| `authors` / `contact` | `authors` / `contact` |

## 9. 校验规则

Aprism 从固定代码表发出错误。工具链必须将未知代码视为警告并继续。

| 代码 | 严重级别 | 条件 |
|---|---|---|
| `CHKAPRISM-MANIFEST-001` | error | 未发现清单且无回退匹配。 |
| `CHKAPRISM-MANIFEST-002` | error | `schemaVersion` 缺失或不被支持。 |
| `CHKAPRISM-MANIFEST-003` | error | `id` 不匹配 `^[a-z][a-z0-9_-]{1,63}$`。 |
| `CHKAPRISM-MANIFEST-004` | error | `version` 不是合法的 SemVer 字符串。 |
| `CHKAPRISM-MANIFEST-005` | error | 必填字段缺失（`id`、`version`、`schemaVersion`）。 |
| `CHKAPRISM-MANIFEST-006` | warning | 存在未知字段（向前兼容）。 |
| `CHKAPRISM-MANIFEST-007` | error | `environment` 不在 `*`、`client`、`server`、`dedicated_server` 之内。 |
| `CHKAPRISM-MANIFEST-008` | error | 入口描述符格式错误。 |
| `CHKAPRISM-MANIFEST-009` | error | Mixin 配置文件未找到或非法。 |
| `CHKAPRISM-MANIFEST-010` | error | `accessWidener` 路径未找到。 |
| `CHKAPRISM-MANIFEST-011` | error | BE 清单缺失 `aprism` 对象，且 pack 并非原生 Bedrock pack。 |
| `CHKAPRISM-MANIFEST-012` | error | `aprism.language` 不在允许集合内。 |
| `CHKAPRISM-MANIFEST-013` | error | 非 Script 语言缺失 `aprism.nativeEntrypoints`。 |
| `CHKAPRISM-DEP-001` | error | 缺少硬依赖。 |
| `CHKAPRISM-DEP-002` | error | 依赖版本不匹配。 |
| `CHKAPRISM-DEP-003` | error | `breaks` 约束被违反。 |
| `CHKAPRISM-DEP-004` | warning | 重复 `provides` 别名；较低版本被卸载。 |
| `CHKAPRISM-DEP-005` | error | 检测到循环依赖。 |
| `CHKAPRISM-DEP-006` | warning | `conflicts` 约束匹配；继续。 |
| `CHKAPRISM-DEP-007` | error | 保留依赖（`aprism`/`minecraft`/`java`）失败。 |
| `CHKAPRISM-RANGE-001` | error | 版本范围语法非法。 |

## 10. 多语言模组清单

`language` 字段选择运行时与入口契约。默认值：JE = `java`；BE = `javascript`（Script API），除非 `aprism.language` 另行声明。

| `language` | 运行时 | 入口契约 |
|---|---|---|
| `java` | JVM classloader | 类名或 `Class::method`（第 3.3 节）。 |
| `cpp` | 原生 dlopen/LoadLibrary | C ABI 工厂 `extern "C" IAprismMod* aprism_mod_create()`；可选平台入口 `aprism_mod_load`（第 4.2 节示例与文档 8 §6.2）。 |
| `lua` | 嵌入式 Lua 5.x / LuaJIT（JE）或 Bedrock Lua（BE） | 指向含 `function aprism_init(ctx)` 的 `.lua` 文件的字符串路径。 |
| `csharp` | .NET CLR 宿主（JE）/ BE 上的原生 .NET | 指向程序集的路径；静态方法 `AprismInit`。 |
| `rust` | 原生，同 `cpp` | 同 `cpp`：C ABI 工厂 `aprism_mod_create`（Rust `extern "C"`）。 |
| `javascript` | GraalJS（JE）/ Bedrock Script API（BE） | 指向含默认导出 `init` 的 `.js` 模块的路径。 |

对 JE 上的非 Java 语言，入口描述符为对象：`{"adapter": "<language>", "value": "<path-or-symbol>"}`。`languageAdapters` 映射必须为该 adapter id 包含一条条目，可选择指向 Aprism 内置 adapter（`aprism:lua`、`aprism:csharp`、`aprism:graaljs`、`aprism:native`）。

```json
{
  "language": "lua",
  "entrypoints": {
    "main": [ { "adapter": "aprism:lua", "value": "scripts/main.lua" } ]
  },
  "languageAdapters": { "aprism:lua": "io.aprism.loader.lang.LuaAdapter" }
}
```
