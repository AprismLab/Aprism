# v26.9 Release Notes

> Aprism Loader v26.9 — AEP editor capability + extension version metadata
> Author: BlockConnect@StarsailsClover
> Status: DRAFT (v26.8-Alpha.8 in progress; final on v26.9 GA)

## Overview

The v26.9 line turns AprismWarp's read-only Node-side capability index
into a backward-compatible, declarative AEP metadata field. The runtime
AEP contract is unchanged: the editor catalog is optional, ignored by
Aprism runtime, and safe to omit on any AEP produced before v26.9. The
new metadata ships today in every Refract branch as part of the
AEP-format-adaptation release (`fabric|neoforge|forge|quilt|liteloader/
v26.9-Alpha.2`).

## Alpha line

### Alpha.1 — AprismWarp catalog opt-in (lives in Aprism v26.8-Alpha.8)

- Optional root-level `aprismwarp.editor.json` accepted by the packaging
  plugin. Schema: `aprismwarp.aep-editor/v1`. The catalog is a declaration
  only; Aprism runtime ignores it, AprismWarp reads it without loading the
  extension jar.
- Extension manifests gain an optional `version` (SemVer) field, consumed
  by Aprism runtime for extension dependency range matching. Omitted value
  preserves v26.8 behavior.
- AprismPackagingExtension exposes `editorManifestFile`; AprismPackagingPlugin
  wires it through to every `packageAep` task. Legacy AEPs without the
  catalog remain installable.
- PackageAepTaskTest covers: root `aprism.extension.json` present, root
  `aprismwarp.editor.json` present, embedded extension jar present.

### Alpha.2 — Refract adoption (v26.9-Alpha.2)

All five Refract branches emit the editor catalog in every variant and
declare an extension self-version. Upstream SDK document updated with the
catalog rules and the Gradle DSL configuration
(`aprismPackaging.editorManifestFile`).

- 32/32 AEP variants structurally validated (root manifest + root editor
  catalog + one embedded jar).
- Five workflow_dispatch runs published five Pre-Releases with cosign
  keyless signatures and CycloneDX SBOMs.
