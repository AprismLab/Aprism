# Aprism Loader v26.5 — 已知问题

> v26.5 官方版的配套文档。维护者：BlockConnect@StarsailsClover。条目按主题排列，不按严重度；均为随 v26.5 GA 明确知悉而发布的事项。v26.3 至 v26.5 期间关闭的条目标注 [CLOSED]，保留以便历史追溯。

## JE 加载器核心

1. **[v26.5-Alpha.3 已关闭] 无游戏事件分发。** v26.3-Alpha.1 的游戏事件分发器是被动的；v26.5-Alpha.3 新增 `GameEventHookInstaller`，通过 `MethodHookRegistry` 将 MC 的 tick/渲染/世界方法桥接到 `GameEventDispatcher`。钩子目标由平台适配层提供（核心从不硬编码 MC 类名）；无平台适配器时分发器保持 fail-closed。
2. **[v26.3-Alpha.2 已关闭] 注册表仅有泛型能力。** `AprismRegistry` 与 `registry/` 子包暴露泛型注册表 API。绑定到真实 Minecraft 游戏注册表的类型化 Block/Item/Entity 注册表尚不存在。
3. **[v26.3-Alpha.3 已关闭] 无网络 API。** JE 生态的包（packet）API 均无 Aprism 等价物。需要自定义数据包的模组必须使用 Mixin。
4. **[v26.5-Alpha.1 已关闭] 入口点发现仅依赖清单。** 注解扫描回退已加入：清单未声明 `main` 入口点时，加载器扫描嵌入 jar 中的 `@AprismMod` 类。

## Loader 支持（目标 #4，已于 v26.2-Alpha.5 关闭）

5. **外部分发仅走 SPI。** 自 v26.2-Alpha.5 起，核心不再携带内置外部 loader 桥接。外部 loader 模组目录仅在其 `.aep` loader-support 扩展已安装时被扫描，其模组仅在扩展的 `LoaderEntrypointHandler` 已注册时被分发。没有注册处理器的外部模组会被发现但永不执行。
6. **[已于 v26.5-Alpha.2 关闭] 扩展依赖区间仅做存在性校验。** 扩展间的 `depends` 现已按依赖扩展的 `version` 字段执行完整 SemVer 区间匹配；对无版本清单保留存在性校验作为向后兼容回退。

## 游戏侧驱动（v26.5 安装器）

18. **v26.5 安装器需要平台适配器才能驱动真实游戏。** v26.5 线交付了 `GameEventHookInstaller`、`CommandBindingInstaller`、`KeyBindingBindingInstaller`、`TickSchedulerDriver`、`ResourceReloadTrigger` 与 `NetworkTransportInstaller`。每者遵循同一契约：核心提供注册表/门面接线与桥接接口（`CommandDispatcherBridge`、`InputSystemBridge`、`NetworkTransport`、钩子目标描述符）；AprismRefract 分支或平台适配器提供 MC 版本特定的绑定。无适配器时所有表面保持仅注册且 fail-closed。适配器本身随各自的 Refract 线交付。

## 深度 API 线（v26.4 新增）

16. **深度能力在原生 JVM 上仅为契约 + 注册表。** v26.4 深度 API（字节码
    钩子、JVM 内省、原生互操作、AprismateAgent 检测、硬件洞察、跨语言
    运行时）以被证明的能力契约交付。硬件支撑与 FFM 支撑的实现在
    AprismJDK 线中；在原生 JVM 上每项深度操作均优雅降级（仅被证明的
    值、fail-closed 拒绝、绝不向游戏抛异常）。
17. **AprismJDK 本身仍处于其早期线。** AprismJDK 子项目（OpenJDK 变体
    + AprismateAgent）跟踪其自有版本线，尚非可下载的 JDK；在此期间
    Aprism 完全运行在原生 OpenJDK 上。

## 加载器生态同款（v26.3 新增）

14. **同款面是注册契约。** v26.3 在加载器 API 层面关闭了 Forge/NeoForge 的 EventPriority + InterModComms 同款，以及 Fabric 的命令/按键/tick 调度器/资源重载同款。v26.5 线（Alpha.3~8）为这些表面补齐了真实驱动的安装器层；实际游戏侧绑定仍需平台适配器（见条目 18）。
15. **[v26.5-Alpha.1 已关闭] 无注解扫描入口发现**（见条目 4）。

## 基岩版（Bedrock Edition）

7. **目前仅 Java 侧。** v26.1 交付了完整的 Java 侧 BE 基础（版本库、注入计划、协调器、原生安置、版本适配器）。原生平台注入器（Windows 代理 DLL、Android Zygisk/容器、iOS）尚未实现；详见 BE 方案研究报告（`docs/research/bedrock-approach/`）。BE 工作保持冻结，直至 9 月逆向工程里程碑。
8. **无真实游戏 BE 冒烟。** 本机未安装 Minecraft 基岩版，BE 行为仅由单元/集成测试验证。
9. **封禁风险。** 在启用 Xbox Live 的存档上进行 BE 原生修改存在真实的封禁风险。请使用离线存档。已在 Doc 01 §13.2 披露。

## 真实游戏验证

10. **Harness 覆盖仅 JE 26.2。** MDL 驱动的真实游戏冒烟针对 Minecraft 26.2（JDK 25）运行。26.1.2 与旧版本线（1.16.5 / 1.21.x）由版本线注册表配置与单元测试覆盖，无真机运行。
11. **MDL 无 `-javaagent` 配置键。** Harness 直接用 agent 启动游戏；MDL 用于实例/日志/游戏控制。更深入的 MDL 集成已在计划中。

## 分发

12. **仅独立下载。** Aprism 不上架 Microsoft Store 与 Apple App Store（两者均禁止商店分发应用中的动态代码注入）。
13. **[已于 v26.6-Alpha.3 关闭] Modrinth 镜像尚未发布。** 发布工作流现已将每个签名制品镜像至 Modrinth（以 MODRINTH_TOKEN 门控）；GitHub Releases 仍是主要的、校验权威的渠道。
