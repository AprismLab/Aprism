# Aprism Mods Pack (.aje/.abe) 分类、结构与各平台放置位置

> 文档 7 / 8 | Aprism Loader 文档集
> 版本：v26.0-Alpha1-Phase0 | 状态：开发中

> 规范语言：英文（中文副本同步维护）

## 1. 执行摘要

Aprism 以两种统一的 pack 格式分发模组：用于由 Aprism javaagent 加载的 Java Edition 内容的 `.aje`（Aprism Java Edition pack），以及用于由 Aprism native loader 加载的 Bedrock Edition 内容的 `.abe`（Aprism Bedrock Edition pack）。两种格式均为 ZIP 容器，根目录携带 `aprism.manifest.json` 以及各版本特定的载荷。单个产物可通过拷贝、启动器中介放置或双击导入进行安装，并具备足够的自描述能力，以便在任何 class 或 native binary 被触碰之前完成校验。

本文档是 pack 分类、内部结构、清单放置位置以及 pack 安装时所采用的各平台精确目录位置的规范参考。它约束启动器集成、安装器工具以及第三方打包工具。本文档记录的放置路径是规范性的：任何偏离这些路径的启动器都会破坏加载发现机制，属于不符合规范。

## 2. Pack 分类

Aprism 识别两种顶层 pack 扩展名，二者均以 ZIP 为底层容器。扩展名决定由哪个 Aprism 子系统消费该 pack；清单的 `type` 字段决定所采用的语言运行时与 entrypoint 契约。

### 2.1 .aje - Aprism Java Edition Pack

`.aje` pack 是一个 ZIP，根目录包含 `aprism.manifest.json`、一个或多个 Java 归档（`<modid>.jar` 或按 loader 分类的 jar）、可选的平台子目录（`fabric/`、`forge/`、`neoforge/`、`quilt/`、`liteloader/`）、共享的 `resources/`、位于 `mixins/` 下的 Mixin 配置，以及可选的位于 `lib/` 下的捆绑库。Aprism javaagent 会扫描活动实例的 `mods/` 目录，打开每个 `.aje`（以及任何同目录下的 `.jar`），校验清单，并将该模组注册至 loader 核心。

### 2.2 .abe - Aprism Bedrock Edition Pack

`.abe` pack 是一个 ZIP，根目录包含 `aprism.manifest.json` 以及一份 Bedrock 形态的载荷：`behavior_pack/` 与 `resource_pack/` 子目录（各自携带自己的 Bedrock `manifest.json` 以保证原生 Bedrock 兼容性）、可选的 `scripts/` 目录（用于 Script API 模组），以及可选的 `native/` 目录（包含按平台划分的 native mod binary：`windows-x64`、`android-arm64`、`android-armv7`、`ios-arm64`、`linux-x64`）。Aprism native loader 消费该 pack：script 组件被安装到标准 Bedrock `behavior_packs/` 树中并按世界注册，而 native 组件则被安装到 `com.mojang/` 下由 Aprism 引入的 `aprism_mods/` 目录中。

### 2.3 按 `type` 子分类

清单的 `type` 字段决定运行时与 entrypoint 契约：

| `type` 取值 | 运行时 | 典型载荷 | 说明 |
|---|---|---|---|
| `native` | C++ / Rust | `native/<platform>/<modid>.{dll,so,dylib}` | 仅 BE；由 Aprism native loader 加载 |
| `script` | JavaScript / TypeScript | `scripts/*.js`（+ sourcemaps） | 仅 BE；标准 Bedrock Script API |
| `hybrid` | Native + Script | `native/` + `scripts/` | 仅 BE；native binary 调用 Script API |
| `converted` | 由 Java 投影至 BE | 由 JE 资产合成的 `behavior_pack/` | 仅 BE；JE-to-BE 转换的输出 |
| `java`（`.aje` 的默认值） | JVM | `<modid>.jar` + 按 loader 的 jar | 仅 JE |

### 2.4 与相邻格式的对比

| 属性 | `.aje` | `.abe` | `.jar` | `.mcpack` | `.mcaddon` |
|---|---|---|---|---|---|
| 容器 | ZIP | ZIP | ZIP | ZIP | ZIP |
| 消费者 | Aprism javaagent | Aprism native loader | 特定 loader（Fabric/NeoForge/等） | Bedrock 引擎 | Bedrock 引擎 |
| 清单 | `aprism.manifest.json` | `aprism.manifest.json` | `fabric.mod.json` / `neoforge.mods.toml` / `META-INF/MANIFEST.MF` | `manifest.json` | `manifest.json`（一个或多个） |
| 多 loader | 是（按 loader 的子目录） | 不适用 | 否 | 不适用 | 不适用 |
| Native binary | 否 | 是（`native/`） | 否 | 否 | 否 |
| Script API | 否 | 是（`scripts/`） | 否 | 是（BP） | 是（BP） |
| 目标版本 | JE | BE | JE | BE | BE |
| Aprism 原生 | 是 | 是 | 通过回退消费 | 不消费 | 不消费 |

## 3. .aje Pack 结构

### 3.1 完整目录树（规范）

```
my-mod-1.0.0.aje                              (ZIP container)
|
+-- aprism.manifest.json                       (REQUIRED, at ZIP root)
+-- my-mod.jar                                 (REQUIRED if no per-loader jar; main mod code)
+-- icon.png                                   (optional, pack icon)
|
+-- fabric/                                    (optional, Fabric-specific jar)
|   +-- my-mod-fabric.jar
|
+-- neoforge/                                  (optional, NeoForge-specific jar)
|   +-- my-mod-neoforge.jar
|
+-- forge/                                     (optional, Forge-specific jar)
|   +-- my-mod-forge.jar
|
+-- quilt/                                     (optional, Quilt-specific jar)
|   +-- my-mod-quilt.jar
|
+-- liteloader/                                (optional, LiteLoader legacy)
|   +-- my-mod.litemod
|
+-- resources/                                 (optional, shared assets)
|   +-- assets/
|   |   +-- my-mod/
|   |       +-- textures/
|   |       +-- lang/
|   |       +-- models/
|   +-- data/
|   |   +-- my-mod/
|   |       +-- recipes/
|   |       +-- loot_tables/
|   +-- pack.mcmeta                            (resource-pack metadata, if shipped as RP)
|
+-- mixins/                                    (optional, Mixin configs)
|   +-- my-mod.mixins.json
|   +-- my-mod.client.mixins.json
|
+-- lib/                                       (optional, bundled dependencies, JiJ-style)
    +-- net/
        +-- example/
            +-- somelib/
                +-- somelib-2.1.0.jar
```

### 3.2 组件参考

| 路径 | 必填 | 用途 |
|---|---|---|
| `aprism.manifest.json` | 是 | 清单；Aprism 唯一首先读取的文件 |
| `<modid>.jar` 或 `<modid>-common.jar` | 是（二者之一） | 主模组代码；当没有按 loader 的 jar 匹配活动 loader 时使用 |
| `fabric/<modid>-fabric.jar` | 否 | Fabric 专有的覆盖项与 entrypoints |
| `neoforge/<modid>-neoforge.jar` | 否 | NeoForge 专有的覆盖项与 entrypoints |
| `forge/<modid>-forge.jar` | 否 | Forge 专有的覆盖项与 entrypoints |
| `quilt/<modid>-quilt.jar` | 否 | Quilt 专有的覆盖项与 entrypoints |
| `liteloader/<modid>.litemod` | 否 | LiteLoader 旧版模组（含 `litemod.json` 的 zip） |
| `resources/` | 否 | 合并至游戏虚拟文件系统的共享资产 |
| `mixins/` | 否 | 由清单 `mixins` 数组引用的 Mixin 配置 JSON |
| `lib/` | 否 | 捆绑库，JiJ 风格；加入该模组的隔离 classloader |
| `icon.png` | 否 | 在启动器与 Aprism UI 中展示的 pack 图标 |

### 3.3 目录树示例

**单 loader 模组（仅 Fabric）：**

```
simple-mod-1.0.0.aje
+-- aprism.manifest.json
+-- simple-mod.jar
+-- mixins/
    +-- simple-mod.mixins.json
```

**多 loader 模组（Fabric + NeoForge + Forge）：**

```

+-- aprism.manifest.json
+-- cross-loader-common.jar
+-- fabric/
|   +-- cross-loader-fabric.jar
+-- neoforge/
|   +-- cross-loader-neoforge.jar
+-- forge/
|   +-- cross-loader-forge.jar
+-- resources/
|   +-- assets/
+-- mixins/
    +-- cross-loader.mixins.json
```

**含 native 组件的模组（对 `.aje` 而言较为罕见；例如 JNI shim）：**

```
jni-shim-0.4.0.aje
+-- aprism.manifest.json
+-- jni-shim.jar
+-- lib/
|   +-- native/
|       +-- windows-x64/
|       |   +-- jni-shim.dll
|       +-- linux-x64/
|           +-- jni-shim.so
+-- mixins/
    +-- jni-shim.mixins.json
```

## 4. .abe Pack 结构

### 4.1 完整目录树（规范）

```
my-be-mod-1.0.0.abe                           (ZIP container)
|
+-- aprism.manifest.json                       (REQUIRED, at ZIP root - Bedrock superset)
|
+-- behavior_pack/                             (optional, standard Bedrock BP)
|   +-- manifest.json                          (REQUIRED if BP present; Bedrock native)
|   +-- pack_icon.png
|   +-- entities/
|   +-- items/
|   +-- blocks/
|   +-- loot_tables/
|   +-- trading/
|   +-- scripts/                               (Script API JS/TS, if script-type mod)
|   |   +-- main.js
|   |   +-- main.js.map
|   +-- texts/
|       +-- en_US.lang
|       +-- languages.json
|
+-- resource_pack/                             (optional, standard Bedrock RP)
|   +-- manifest.json                          (REQUIRED if RP present; Bedrock native)
|   +-- pack_icon.png
|   +-- textures/
|   +-- models/
|   +-- sounds/
|   +-- texts/
|
+-- scripts/                                   (optional, top-level Script API for hybrid/converted)
|   +-- main.js
|
+-- native/                                    (optional, per-platform native binaries)
|   +-- windows-x64/
|   |   +-- my-be-mod.dll
|   +-- android-arm64/
|   |   +-- my-be-mod.so
|   +-- android-armv7/
|   |   +-- my-be-mod.so
|   +-- ios-arm64/
|   |   +-- my-be-mod.dylib
|   +-- linux-x64/
|       +-- my-be-mod.so
|
+-- icon.png                                   (optional, Aprism-side pack icon)
```

### 4.2 组件参考

| 路径 | 必填 | 用途 |
|---|---|---|
| `aprism.manifest.json` | 是 | Aprism 清单；承载 `aprism` 对象的 Bedrock 超集 |
| `behavior_pack/` | 否（script/hybrid/converted） | 标准 Bedrock behavior pack；携带自己的 `manifest.json` |
| `behavior_pack/scripts/` | 否 | 用于 `script` 或 `hybrid` pack 的 Script API 源码 |
| `resource_pack/` | 否 | 标准 Bedrock resource pack；携带自己的 `manifest.json` |
| `scripts/` | 否 | 用于未内嵌于 BP 的 `hybrid`/`converted` pack 的顶层 Script API 源码 |
| `native/` | 否 | 用于 `native` 或 `hybrid` pack 的按平台 native binary |
| `native/<platform>/` | 视情况 | 每个目标平台一个目录；当 `native/` 存在时必填 |
| `icon.png` | 否 | 在 Aprism UI 中展示的 pack 图标 |

### 4.3 Native 平台目录名

| 目录 | 目标 |
|---|---|
| `native/windows-x64/` | Windows UWP Bedrock（x64）、Windows BDS |
| `native/android-arm64/` | Android 64 位 ARM（Android 12+ 目标） |
| `native/android-armv7/` | Android 32 位 ARM（旧设备） |
| `native/ios-arm64/` | 经由 TrollStore 的 iOS（arm64） |
| `native/linux-x64/` | Linux BDS（x64） |

## 5. 清单在 Pack 内的位置

### 5.1 .aje pack

清单为位于 ZIP 根的 `aprism.manifest.json`。Aprism 打开归档、列出根条目并直接读取清单。对 `.aje` pack 不进行子目录扫描；若清单不在根目录，该 pack 将作为格式错误被拒绝。

### 5.2 .abe pack

Aprism 清单 `aprism.manifest.json` 位于 ZIP 根。与之并列，标准 Bedrock `manifest.json` 文件位于 `behavior_pack/` 与 `resource_pack/` 之内。这种双清单设计使 Bedrock 引擎能够原生消费 BP/RP（它只看到 Bedrock 清单），同时 Aprism 读取超集清单以获取 native binary、script 与 hybrid 信息。Aprism 清单的 `aprism` 对象不会重复 Bedrock 已要求的任何字段；它仅添加 Aprism 专有元数据（native binary 映射、script 入口、hybrid 声明、Aprism API 范围）。

### 5.3 发现顺序

当 Aprism 遇到一个 pack（通过目录扫描或导入事件）时，按以下发现顺序处理：

1. 打开归档并在 ZIP 根寻找 `aprism.manifest.json`。
2. 若找到，则解析并进行 schema 校验；该结果为权威。
3. 若在 `.aje` 中未找到，则按以下顺序探测旧版清单：`fabric.mod.json`（根目录或任意 jar 内部）、`META-INF/neoforge.mods.toml`、`META-INF/mods.toml`、`litemod.json`。首个命中项被投影为内存中的 Aprism 清单。
4. 若未找到任何类型的清单，该 pack 被拒绝并记录日志。

## 6. 各平台放置指南（JE）

### 6.1 放置表

| 平台 | 操作系统 | 路径 | 说明 |
|---|---|---|---|
| Vanilla 启动器 | Windows | `%APPDATA%\.minecraft\mods\` | Aprism 默认安装目标 |
| Vanilla 启动器 | macOS | `~/Library/Application Support/minecraft/mods/` | Aprism 会正确解析 `~` |
| Vanilla 启动器 | Linux | `~/.minecraft/mods/` | 约定位置 |
| Prism Launcher | 任意 | `<instance>/mods/` | 按实例隔离 |
| MultiMC / PolyMC | 任意 | `<instance>/mods/` | 与 Prism 相同 |
| ATLauncher | 任意 | `<instance>/mods/` | 按实例 |
| CurseForge App | Windows | `<instance>/mods/` | 按 profile 限定路径 |
| Android JE（PojavLauncher） | Android | `/sdcard/Android/data/net.kdt.pojavlaunch/files/.minecraft/mods/` | 路径可能随启动器构建版本变化 |
| Android JE（PojavLauncher，scoped storage） | Android 11+ | `/sdcard/Android/data/net.kdt.pojavlaunch/files/games/PojavLauncher/.minecraft/mods/` | Scoped-storage 布局 |

### 6.2 Aprism javaagent 扫描行为

在 `premain` 时，Aprism javaagent 从系统属性 `aprism.instance.root`（由启动器设置）解析活动 Minecraft 实例根目录，若未设置则回退至宿主操作系统的默认 `.minecraft` 位置。它枚举 `<instance>/mods/` 下每一个以 `.aje` 或 `.jar` 结尾的文件。对 `.aje`，就地打开归档并读取清单而无需解压。对 `.jar`，应用旧版发现顺序（第 5.3 节，步骤 3）。

模组按由清单 `depends` 图计算出的依赖顺序加载。同一 `id` 不同版本的模组会被去重；较高 SemVer 胜出，较低者被记录为 shadowed。在同一 `mods/` 目录中混用 `.aje` 与 `.jar` 完全受支持；Aprism 将二者同等对待，并合并其依赖图。

### 6.3 与传统 `.jar` 混用

用户可将既有的 Fabric `.jar` 模组与新的 `.aje` pack 并存。Aprism 会同时加载二者。唯一规则：若某个 `.jar` 与某个 `.aje` 声明相同的 `id`，则 `.aje` 胜出，因为它携带 `.jar` 无法承载的 Aprism 专有元数据。`.jar` 被记录为 shadowed。

## 7. 各平台放置指南（BE）

### 7.1 放置表

| 平台 | 操作系统 | `com.mojang` 路径 | `aprism_mods` 路径 | 说明 |
|---|---|---|---|---|
| Bedrock UWP | Windows | `%LocalAppData%\Packages\Microsoft.MinecraftUWP_*\LocalState\games\com.mojang\` | `...\com.mojang\aprism_mods\` | 通配符匹配带版本号的 package family name |
| Bedrock Android | Android <= 10 | `/sdcard/games/com.mojang/` | `/sdcard/games/com.mojang/aprism_mods/` | 共享存储；无 scoped-storage 限制 |
| Bedrock Android | Android 11 | `/sdcard/games/com.mojang/` | `/sdcard/games/com.mojang/aprism_mods/` | Scoped storage 对 `games/` 的读取予以豁免；写入需 MANAGE_EXTERNAL_STORAGE 或 SAF |
| Bedrock Android | Android 12+ | `/sdcard/Android/data/com.mojang.minecraftpe/files/games/com.mojang/` | `...\com.mojang\aprism_mods\` | 应用专属外部存储；无需额外权限 |
| Bedrock iOS | iOS | Minecraft 容器（Files app） | 容器内的 `Minecraft/aprism_mods/` | native loader 需 TrollStore；仅 script 模组不需要 |
| Bedrock Dedicated Server | Windows | `<bds-root>\games\com.mojang\` | `<bds-root>\games\com.mojang\aprism_mods\` | BDS 安装根目录 |
| Bedrock Dedicated Server | Linux | `<bds-root>/games/com.mojang/` | `<bds-root>/games/com.mojang/aprism_mods/` | BDS 安装根目录 |

### 7.2 各组件的去向

**Native mod binary（`.abe` 的 `native/` 载荷）：** 解压至 `com.mojang/aprism_mods/<modid>/native/<platform>/`。Aprism native loader 在启动时扫描 `aprism_mods/`，将运行平台与 `<platform>` 目录名匹配，仅加载匹配的 binary。`aprism_mods/` 由 Aprism 引入，Bedrock 引擎本身不读取该目录。

**Script API 模组源码（`.abe` 的 `behavior_pack/scripts/` 或 `scripts/`）：** 安装至 `com.mojang/development_behavior_packs/<modid>/scripts/`（开发用，热重载）或 `com.mojang/behavior_packs/<modid>/scripts/`（稳定）。随后通过向 `minecraftWorlds/<world>/world_behavior_packs.json` 追加该 BP 的 UUID 与版本以按世界注册。

**Behavior 与 resource pack 内容：** 按 Bedrock 预期的方式安装至 `behavior_packs/` 与 `resource_packs/`；Aprism 不修改 Bedrock 的 BP/RP 加载行为。

### 7.3 Aprism native loader 扫描行为

在注入时，Aprism native loader 枚举 `aprism_mods/*/aprism.manifest.json`。对每个清单，它将平台条目与运行宿主进行校验，打开 `<modid>/native/<platform>/<modid>.<ext>`，若存在签名则进行校验（第 10 节），并调用 loader entrypoint。Native mod 是全局的；它们不按世界划分。

### 7.4 Bedrock 引擎对 script 部分的加载

Script 组件由 Bedrock 引擎通过标准 BP 机制加载。Aprism 仅确保 BP 已落盘于 `behavior_packs/`（或 `development_behavior_packs/`）中，并且 BP 的 UUID 已在 `world_behavior_packs.json` 中为每个应运行该模组的世界注册。script 执行无需 Aprism 侧的 hook；一旦注册完成，Bedrock 自身的 script 运行时即会加载并执行 JS/TS。

## 8. Pack 安装方式

### 8.1 手动拷贝

用户按第 6、7 节将 `.aje` 或 `.abe` 文件拷贝至正确目录。无需更新元数据；Aprism 在下次启动时发现该 pack。这是摩擦最小的方式。

### 8.2 启动器中介放置

与 Aprism 集成的启动器调用 Aprism Installer API 以放置 pack 并更新世界注册 JSON。对 BE script 模组，启动器将 BP UUID 追加至所选世界的 `world_behavior_packs.json`。对 BE native 模组，启动器将 binary 解压至 `aprism_mods/<modid>/native/<platform>/`。启动器在写入 `com.mojang/` 之前必须解析活动 Minecraft 包路径。

### 8.3 双击导入

Aprism 在 Windows、macOS 与 Linux 桌面上为 `.aje` 与 `.abe` 注册文件关联。双击 pack 将启动 Aprism Importer，该校验 pack、提示选择目标 Minecraft 实例（JE）或世界范围（BE），并执行安装。在不具备桌面的 BE 平台（Android、iOS）上，导入在 Aprism 伴侣应用内完成。

### 8.4 世界范围 vs 全局

- **JE：** 所有模组对实例全局；不按世界划分。
- **BE native mod：** 全局。`aprism_mods/` 不按世界划分；native binary 在进程启动时加载一次。
- **BE script mod：** 按世界划分。BP 必须在 `world_behavior_packs.json` 中为每个应运行该 script 的世界注册。Aprism 的安装器可按需在多个世界中批量注册。

## 9. Pack 校验

在任何 class 或 native binary 加载之前，Aprism 通过固定的流水线对每个 pack 进行校验。任何阶段失败即拒绝该 pack 并记录原因；其余 pack 继续。

| 阶段 | 检查 | 失败处理 |
|---|---|---|
| 1. ZIP 完整性 | 打开归档；校验中央目录与 CRC | 拒绝；记录 "corrupt archive" |
| 2. 清单存在性 | 根目录存在 `aprism.manifest.json`，或可发现旧版清单 | 拒绝；记录 "no manifest" |
| 3. 清单 schema | JSON 格式良好；必填字段存在；类型合法 | 拒绝；记录带字段路径的 schema 错误 |
| 4. Native 平台匹配 | 对 `.abe` 的 `native/` 载荷，宿主平台目录存在 | 跳过 native 加载；记录 "no binary for <platform>"；若为 hybrid 则回退为仅 script |
| 5. Minecraft 版本范围 | `minecraft` 范围与运行中的 Minecraft 版本相交 | 拒绝；记录 "incompatible Minecraft version" |
| 6. Aprism API 范围 | `aprismApi` 范围与运行中的 Aprism API 版本相交 | 拒绝；记录 "incompatible Aprism API" |
| 7. Java 版本（`.aje`） | `java` 范围与运行中的 JDK 版本相交 | 拒绝；记录 "incompatible Java" |
| 8. 依赖解析 | 所有 `depends` 条目可在模组集中解析 | 拒绝；记录缺失的依赖 |
| 9. 冲突检查 | 没有 `breaks` 条目被任一已安装模组匹配 | 拒绝；记录冲突 |
| 10. 签名（若已签名） | Cosign 签名针对 bundle 校验通过 | 应用未签名模组策略（第 10 节） |

## 10. Pack 签名（可选但推荐）

### 10.1 经 Cosign 签名的 bundle

Aprism 建议 pack 作者使用 cosign keyless 签名对 `.aje` 与 `.abe` bundle 进行签名（与 Aprism 发布产物所用机制相同，见文档 1 第 8 节）。签名为 detached 形式，作为 `<pack>.sig` 与 `<pack>.bundle` 与 pack 一并分发。在加载时，Aprism 针对配置的证书身份（GitHub OIDC issuer、workload identity 或固定公钥）校验签名。

### 10.2 加载时的签名校验

校验发生在校验流水线的第 10 阶段（第 9 节）。成功时，pack 被标记为 `signed` 并运行，不再受进一步限制。失败时，应用未签名模组策略。

### 10.3 未签名模组 allowlist 策略

未签名模组策略按实例与按版本配置：

- `allow`（开发实例的默认值）：未签名模组加载，并记录一条警告日志。
- `warn`：未签名模组加载，但在首次启动前在 UI 上弹出警告。
- `deny`：未签名模组被拒绝；仅经 cosign 校验的 pack 加载。

对 BE native mod，iOS（TrollStore）与 BDS 上默认为 `deny`，其他平台默认为 `warn`，因为无可验证来源的 native 代码执行风险更高。可由用户按实例覆盖。

## 11. 从既有格式迁移

### 11.1 `.jar`（Fabric）迁移至 `.aje`

| 步骤 | 操作 |
|---|---|
| 1 | 运行 `aprism convert --in my-mod.jar --out my-mod.aje` |
| 2 | 工具读取 `fabric.mod.json` 并合成 `aprism.manifest.json` |
| 3 | 原 jar 成为 pack 根目录下的 `<modid>.jar`（作为 common jar 对待） |
| 4 | 来自 `fabric.mod.json` 的 Mixin 配置移至 `mixins/`；清单的 `mixins` 数组被重写以指向它们 |
| 5 | 若存在 access widener 文件，移至 pack 根目录，并重写清单的 `accessWidener` 路径 |
| 6 | 所得 `.aje` 可由 Aprism 直接加载，无需进一步改动 |

### 11.2 `.mcpack` / `.mcaddon` 迁移至 `.abe`

| 步骤 | 操作 |
|---|---|
| 1 | 运行 `aprism convert --in my-pack.mcpack --out my-pack.abe` |
| 2 | 工具读取 Bedrock `manifest.json` |
| 3 | BP 目录移至 `behavior_pack/` 之下；RP 移至 `resource_pack/` 之下 |
| 4 | 在根目录合成 `aprism.manifest.json`，将 Bedrock 清单嵌于 `aprism.bedrockManifest` 之下，并复制 header/modules 以保证 native 兼容性 |
| 5 | 若源 pack 包含 scripts，则将其置于 `behavior_pack/scripts/` 之下，并将清单 `type` 设为 `script` |
| 6 | Native binary（普通 `.mcpack` 中不存在）缺省；清单 `type` 默认按来源为 `script` 或 `converted` |

### 11.3 自动化转换工具参考

`aprism convert` CLI 子命令是规范的转换工具。它接受 `--in <path>`、`--out <path>`、`--format {aje,abe}`，以及可选的 `--sign` 以产出经 cosign 签名的输出。转换是确定性的：相同输入产出相同输出字节（除 ZIP 条目时间戳被置零外）。该工具随 Aprism 一并分发，并在文档 3 中说明。
