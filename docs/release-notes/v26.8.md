# v26.8 Release Notes

> Aprism Loader v26.8 - Real pre-26.1 content binding via the cross-mapping chain
> Author: BlockConnect@StarsailsClover

## Overview

The v26.8 line closes DEC-PRE261 Option A: Aprism-native content now binds
into REAL, obfuscated Minecraft releases before 26.1 through the Mojang
official-mapping cross-resolution chain (official name -> runtime name for
classes, fields, methods, and - since Alpha.9 - overload-exact method
signatures). The line also lands the AprismWarp editor capability catalog
in the AEP format and completes the BC project-management compliance pass.

## Alpha line

### Alpha.1 - OfficialMappings foundation

Mojang `client.txt` parser (classes, static fields, methods) with the
reversed-direction discovery: Mojang client.txt lines are
`official -> obfuscated`, opposite to standard ProGuard. Fail-closed
REMAPPED gate wired into the content binder.

### Alpha.2 - Field-level cross mapping

Static field translation (`BuiltInRegistries.ITEM/BLOCK`) so registry
handles resolve on obfuscated runtimes.

### Alpha.3 - Mapping-aware bootstrap gate

`GameBootstrapGate.setProbeNames` translates the vanilla bootstrap probe
(`net.minecraft.server.Bootstrap`/`checkBootstrapCalled`) through the
loaded mappings (1.21.4: `akx`/`a`), so deferred mod lifecycle dispatch
works on obfuscated profiles instead of racing vanilla bootstrap.

### Alpha.4 - Identifier factory translation

The identifier factory (`parse`) resolves through the mappings
(1.21.4: `akv.a`), with the 26.x `Identifier` -> pre-26.1
`ResourceLocation` fallback retained.

### Alpha.5 - Registry key + setId chain

`Registries.ITEM/BLOCK` (ResourceKey constants), `ResourceKey.create`,
and `Properties#setId(ResourceKey)` all resolve through the mappings
(1.21.4: `mc.K`, `a`, `b`/`a`), unblocking modern-MC item construction
("Item id not set").

### Alpha.6 - Signature-exact overload resolution

`OfficialMappings` gains a parameter-signature table;
`runtimeMethodName(class, method, paramTypes)` disambiguates same-name
overloads (`containsKey(RL) -> d` vs `containsKey(RK) -> e`), with the
name-only table retained as fallback.

### Alpha.7 - Stack-limit application proven live

`stacksTo(int)`/`maxCount(int)`/`maxStackSize(int)` probed with the
`int` parameter type. Live proof: declared maxStack 16 read back from the
live item as `maxStackSize readback: 'aprism:realsmoke_item' = 16`.

### Alpha.8 - Block property application

`strength(float,float)` and `lightLevel(ToIntFunction)` (reflective Proxy)
applied fail-open. Live proof: `destroyTime=3.0 explosionResistance=6.0`
read back from the live block exactly as declared.

### Alpha.9 - Live end-to-end proof on Minecraft 1.21.4

Genuine obfuscated Minecraft 1.21.4 (JDK 25), harness in
`smoke-harness/1.21.4/`:

- `Content binding: 2/2 unit(s) bound to the live registries`
- `Registry readback: 'aprism:realsmoke_item' present in the live item registry`
- `Registry readback: 'aprism:realsmoke_block' present in the live block registry`
- `maxStackSize readback: 'aprism:realsmoke_item' = 16`
- `block property readback: 'aprism:realsmoke_block' destroyTime=3.0 explosionResistance=6.0`
- Vanilla asset pipeline independently processed the bound block
  (`Missing model for variant: 'aprism:realsmoke_block#'`).
- Real Minecraft 1.21.4 client joined a world under the agent
  (`Player407 joined the game`).

## Also in this line

- AEP editor capability catalog: optional root-level
  `aprismwarp.editor.json`, written by the packaging plugin
  (`aprismPackaging.editorManifestFile`) and read by AprismWarp's
  read-only inspector with post-extraction size hardening (deflate-bomb
  guard). The Aprism runtime remains the extension authority and ignores
  the catalog.
- BC project-management compliance: organization/developer watermarks,
  branch-per-minimum discipline (v26.8 branch), signed commits.

## Known limitations

- Registry presence readback uses parameter-type probing; full
  descriptor-aware matching for exotic overloads remains future work.
- Server-side (dedicated server) content binding parity is not in this
  line.
- Creative-tab inventory presence (`/give` flow through the Despotes
  bridge) is deferred to the v26.9 conformance-harness milestone
  (roadmap section 23); functional evidence above is captured in-world.
